# Get 笔记

两件事共用同一个 biji.com 登录态：

- **同步到本地**：账号里的笔记（录音、链接、文字都算）→ 本地 Markdown，增量更新
- **转逐字稿**：链接或本地音视频交给 Get 转写，取回原文后删掉临时笔记

## 首次准备

```bash
cd <skill-dir> && npm install && npx playwright install chromium
```

Playwright 只在需要登录时打开浏览器。用 `--file` 转本地音视频还要装 ffmpeg（含 ffprobe）。

## 同步到本地

```bash
cd <skill-dir> && OUTPUT_DIR="<笔记目录>" node scripts/sync.js
```

> `<笔记目录>` 是同步结果存放的目录，由用户指定；用户没指定过就问一次，之后同步和检索都用同一个。脚本在此目录下按日期创建子目录。

认证链：缓存 JWT（30min）→ refresh_token 静默刷新（~90天）→ Playwright 浏览器登录（最后手段）。
首次运行需弹出浏览器登录 biji.com，之后约 90 天内无需再开浏览器。

环境变量：
- `OUTPUT_DIR` — 输出目录，即 `<笔记目录>`（默认当前目录下的 `notes/`）
- `SINCE_DATE` — 只同步这天及以后的笔记，格式 `YYYY-MM-DD`（默认全部）
- `TEST_LIMIT` — 测试模式，限制同步条数（默认 `0` = 全部）

## 输出结构

```
<笔记目录>/
  YYYY-MM-DD/
    HHMMSS_标题.md          ← 摘要文件（短录音原文内嵌）
    HHMMSS_标题_原文.md      ← 原文转录（长录音，>50行时分离）
```

## 文件格式

### 摘要文件（主文件）

```yaml
---
date: 2026-03-02
time: "13:21"
title: "标题"
note_id: 1234567890
duration_min: 294
transcript: "HHMMSS_标题_原文.md"  # 长录音才有
场景:                       # AI 待填充
人物: []
话题: []
---
```

内容结构：
- `📑 智能总结` — AI 生成的结构化摘要（录音信息、分类总结、要点）
- `📅 章节概要` — 时间索引 + 每章简介，如 `[13:27](getnotes.seek:360) **AI产品架构讨论**`
- `📋 待办事项` — AI 提取的行动项
- `附件` — 音频链接
- `原文` — 短录音（<50行）时内嵌

### 原文文件（长录音）

```markdown
## [13:27] AI产品架构讨论        ← 章节标题（绝对时间）

[13:27] **②** 你在网上看到...    ← [绝对时间] **说话人** 正文
[13:30] **②** 你查一下...
[13:32] **①** 对。
```

说话人标记：**①②③④⑤**...（同一录音内一致，跨录音不一致）

### 两类文件的核心差异

| | 摘要 | 原文 |
|--|------|------|
| 内容质量 | AI 生成，干净准确 | 原始 STT，噪声多 |
| 信息密度 | 高（浓缩要点） | 低（大量"嗯""对""好"） |
| 关键词准确度 | 高（专有名词正确） | 低（常识别错误） |
| 长度 | 50-100 行 | 300-700+ 行 |
| 适用场景 | 查主题、找事件、看结论 | 查原话、查细节、查时间线 |

## 检索策略

**根目录**：`<笔记目录>/`

### 分层检索（由粗到细）

#### Layer 1：摘要搜索（默认起点）

**适用**：绝大多数查询 — "昨天聊了什么"、"最近讨论过 OAuth 吗"、"哪天提到了健身房"

```
Grep "关键词" --path "<笔记目录>/" --glob "!*_原文.md"
```

**为什么先搜摘要**：摘要是 AI 生成的干净文本，专有名词拼写正确，信息密度高。绝大部分信息都能在摘要里找到。

**搜摘要能回答的问题**：
- 某天讨论了哪些话题 → 看章节概要
- 某个话题的结论/要点 → 看智能总结
- 有什么待办事项 → 看待办事项
- 大致什么时间讨论的 → 看章节概要的时间戳

#### Layer 2：章节索引（定位原文位置）

**适用**：已知哪个文件，需要在长原文中定位具体段落

```
Grep "^## " path/to/HHMMSS_标题_原文.md --output_mode content
```

返回所有章节标题及行号，相当于目录。例：
```
8:## [13:21] 开场与电力改造对接
19:## [13:27] AI产品架构讨论
68:## [13:59] 生活数码闲聊
```

然后用 `Read offset/limit` 只读目标章节。

#### Layer 3：定向原文阅读（需要原话/细节）

**适用**：
- 需要知道某人（①②③）说了什么原话
- 需要对话的上下文和时间线
- 摘要太笼统，想看细节

**方法**：通过 Layer 2 拿到目标章节行号，`Read --offset X --limit 50` 只读该章节。

**绝对不要**：一次性读完整个原文文件。700 行噪声文本会污染上下文、浪费 token。

#### Layer 4：原文全文搜索（最后手段）

**适用**：摘要里搜不到，但你确定说过这件事（可能是闲聊中一句带过，AI 没提炼到摘要里）

```
Grep "关键词" --path "<笔记目录>/" --glob "*_原文.md"
```

**注意 STT 噪声**：
- 专有名词经常识别错误（"happy copy" 可能是某产品名的误识别）
- 用**短词根**搜索比完整词更可靠：搜"健身"而非"健身房"，搜"OAuth"而非"OAuth登录"
- 尝试**多个变体**：如果"服务器"搜不到，试"机房"或"VPS"
- 中英混合内容很常见，技术术语可能是英文原词也可能是中文翻译

### 按场景的检索路径

| 用户问题 | 检索路径 |
|---------|---------|
| "昨天/上周聊了什么" | Glob 日期目录 → 读摘要标题和智能总结 |
| "最近有没有聊过 X" | Layer 1 搜摘要 → 有则读该摘要 |
| "X 具体怎么说的" | Layer 1 定位文件 → Layer 2 找章节 → Layer 3 读原文段落 |
| "某某人说了什么" | Layer 1 找文件 → Layer 3 搜 **①②③** + 关键词 |
| "那天下午 3 点在聊什么" | Glob 日期目录 → Layer 2 找 `[15:` 开头的章节 |
| "确认一下某事是不是这样" | Layer 1 搜摘要，不够再 Layer 3 读原文 |
| "帮我找某个很随意的闲聊" | 直接 Layer 4（闲聊可能不在摘要里） |

### 排除模式

搜索时排除原文文件（减少噪声）：
```
--glob "!*_原文.md"
```

搜索时只搜原文文件：
```
--glob "*_原文.md"
```

## 转逐字稿

```bash
cd <skill-dir> && node scripts/link-transcript.js <链接> --json
cd <skill-dir> && node scripts/link-transcript.js --file <本地路径或媒体直链> --json
```

按来源选路，免费的先走：

| 来源 | 走法 | 额度 |
|------|------|------|
| 抖音、小红书、B 站（认 `?p=N` 分 P）、小宇宙链接 | 链接解析 | 不扣 |
| 链接解析报错，或其他网站的音视频 | 先把音视频下载到本地（比如用 yt-dlp），再 `--file` | 按时长扣 |
| 本地音视频 | `--file` | 按时长扣 |
| YouTube | 不交给 Get：它会抓到错误语言的字幕轨 | — |

`--file` 按音频时长四舍五入到分钟扣每月转写额度，同一个文件重复传也照扣；单个文件上限 3 小时、1GB。动手前告诉用户这次大约扣多少分钟，长的先确认。

`--json` 返回的字段：

- `text`：给用户的正文
- `source`：`get-corrected` 是 Get 按提示词出的纠错稿，直接用；`get-raw`（链接解析）和 `get-upload-raw`（`--file`）是原始识别，专有名词和同音字常错。出不出纠错稿由 Get 决定，同一平台也会变，以这个字段为准
- `raw`：原始识别全文；`corrected`：来源是原始识别时，这里是 Get 的智能总结，不是纠错稿
- `minutes`：`--file` 实际扣的分钟数

### 纠错原始识别

`source` 是原始识别时，交付前纠一遍：按段切成约 3000 字的块，每块只改错别字、同音字和品牌型号等专有名词，补标点，时间戳和分段原样保留，不删、不概括、不改说法。`corrected` 里的智能总结专有名词基本是对的，当作参照。一块纠完长度变化超过 15%，说明被删改了，退回这块的原文。逐字稿长的话，分块交给更便宜的模型并发去做。

### 机制

走网页版逆向接口，复用同步的登录态：建一条临时笔记，取原文，再按 id 彻底删除（含回收站），绝不清空回收站。不用官方 OpenAPI，是因为官方建链接笔记不能带提示词，也不能上传音频。建过的 note_id 记在 `.link-transcript-ids.json`，同步时跳过，不会混进笔记目录。各平台实测记在脚本文件头。`--keep` 保留临时笔记，调试用。

## 辅助脚本

- `rebuild-state.js` — 从 API 重建同步状态（丢失 `.sync-state.json` 时用）
- `dedupe.js` — 去重工具

## 状态文件

- `.sync-state.json` — 已同步的 note_id 列表（增量同步依赖）
- `.token-cache.json` — JWT + refresh_token 缓存
- `.auth-state.json` — Playwright 浏览器登录状态

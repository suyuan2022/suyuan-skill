# 检索 Get 笔记

`<笔记目录>` 是 `<状态目录>/config.json` 里的 `outputDir`；`<状态目录>` 是环境变量 `GET_BIJI_HOME` 的值，没设就是 `~/.config/get-biji/`。下面的命令用 `rg`（ripgrep），没装就换成 `grep -r`。

## 文件

```
<笔记目录>/
  YYYY-MM-DD/
    HHMMSS_标题.md        ← 总结文件，每条笔记一个
    HHMMSS_标题_原文.md    ← 逐字稿，录音转写超过 50 行才单独拆出来
```

总结文件的开头：

```yaml
---
date: 2026-03-02
time: "13:21"
title: "标题"
note_id: 1234567890
note_type: recorder_audio            # 笔记类型，见下
duration_min: 294                    # 录音才有
transcript: "HHMMSS_标题_原文.md"     # 拆出了逐字稿才有
---
```

`note_type` 分清这条是不是用户自己的录音：

- `recorder_audio`、`recorder_flash_audio`：录音卡录的
- `audio`：App 里录的
- `meeting`：会议录音
- `link`：存的链接，文章、视频、播客都算，里面的对话是别人的
- 其他值是文字、图片等笔记

用户问「录音里聊过什么」，只看前三类：

```bash
rg -l "^note_type: (recorder_audio|recorder_flash_audio|audio|meeting)$" "<笔记目录>"
```

正文依次是：`📑 智能总结`（AI 写的摘要和要点）、`📅 章节概要`（每章的时间和简介，形如 `[13:27](https://getnotes.seek:360) **章节名**`，链接只是时间索引，打不开）、`📋 待办事项`、`附件`（音频链接），短录音的逐字稿接在最后。

逐字稿的格式：

```markdown
## [13:27] AI产品架构讨论          ← 章节标题，绝对时间

[13:27] **②** 你在网上看到...      ← [绝对时间] **说话人** 正文
[13:32] **①** 对。
```

说话人 ①②③… 在同一条录音里一致，跨录音不对应同一个人。

总结是 AI 写的，干净，专有名词基本对，几十到一百来行；逐字稿是语音识别原文，有原话和时间，但常有错字，长录音几百上千行。

## 由粗到细地搜

1. **先搜总结**，大多数问题到这一步就够了：

   ```bash
   rg -l "关键词" "<笔记目录>" -g '!*_原文.md'
   ```

   问某一天聊了什么，直接看那天的目录：`ls "<笔记目录>/2026-10-15"`，读每个总结文件的智能总结和章节概要。

2. **要原话或细节**，先列出逐字稿的章节当目录用，再只读目标章节那几十行：

   ```bash
   rg -n "^## " "<逐字稿文件>"
   ```

   逐字稿按章节读，一次读一章。问「那天下午 3 点在聊什么」，就找 `## [15:` 开头的章节。

3. **总结里搜不到，但用户确定说过**（闲聊常常进不了总结），再搜逐字稿全文：

   ```bash
   rg -n "关键词" "<笔记目录>" -g '*_原文.md'
   ```

   语音识别常把专有名词认错，所以用短词根搜（搜「健身」，不搜「健身房」）；搜不到就换说法（「服务器」→「机房」「VPS」）；技术词可能是英文原词，也可能是中文。

问「某人说了什么」：先在总结里定位是哪条录音，再在它的逐字稿里搜这个人的说话人标记（比如 `**②**`）加关键词。
